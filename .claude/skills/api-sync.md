# api-sync

Keep `docs/api/openapi.yaml` and `frontend/src/app/models/*.ts` in sync with whatever the Spring Boot backend exposes via springdoc.

> **Note:** `ci-backend.yml` auto-refreshes `docs/api/openapi.yaml` on push to `dev`. This skill is for **local** sync (before opening a PR) and for the manual frontend type regen which CI does not do.

## Steps

### 1. Boot the backend (or attach to one already running)

If nothing is running on `:8080`:

```bash
cd backend
./mvnw spring-boot:run
```

Wait for the log line `Started ThedogsApplication`. Or, in a separate terminal, point at an already-running instance.

### 2. Fetch the OpenAPI snapshot

```bash
curl -fsS http://localhost:8080/v3/api-docs.yaml -o docs/api/openapi.yaml
```

If the curl fails with 404, springdoc is misconfigured — read `backend/src/main/java/com/thedogs/config/OpenApiConfig.java` and confirm `springdoc.api-docs.path` is `/v3/api-docs`.

### 3. Inspect the diff

```bash
git diff docs/api/openapi.yaml
```

Expected: additions/changes for endpoints added in the most recent feature(s). If you see deletions you didn't expect, that's a regression — investigate before regenerating frontend types.

### 4. Regenerate frontend types

The project uses `openapi-typescript` (per ARCHITECTURE.md §5). From `frontend/`:

```bash
cd frontend
npx openapi-typescript ../docs/api/openapi.yaml -o src/app/models/api.ts
```

If `src/app/models/api.ts` does not exist yet (first run), create the directory structure first.

### 5. Verify the frontend still builds

```bash
npm run lint
npm test -- --run
npm run build -- --configuration=production
```

If any of these fail, the contract change broke a frontend usage site. Fix the usage to match the new types (do not roll back the type regen).

### 6. Commit as one logical change

```bash
git add docs/api/openapi.yaml frontend/src/app/models/api.ts
git commit -m "chore(api): sync OpenAPI snapshot + frontend types"
```

If frontend usage sites also changed in step 5, include them in the same commit:

```bash
git add frontend/src/app/...
git commit --amend --no-edit
```

## Conventions

- Always commit `docs/api/openapi.yaml` and the generated `models/api.ts` together. Splitting them across commits creates a moment where the frontend can't compile.
- Never hand-edit `frontend/src/app/models/api.ts` — it is generated.
- The `api.ts` file may have a `// generated by openapi-typescript@<version>` header. Preserve it.
- If the OpenAPI snapshot changed but `npm run build` did not need any other source changes, the commit is just the two files above. Fast and clean.

## When NOT to use

- The backend hasn't changed since the last successful CI run → snapshot is already fresh; nothing to do.
- The frontend reports a type error but you just upgraded `openapi-typescript` itself → that's a tooling drift, not an API drift. Fix it via `deps-bump` or by re-running step 4 with the new generator.
- You're mid-feature and just want to TRY a contract change → don't commit yet; use a draft change and only sync at the end before opening the PR.
