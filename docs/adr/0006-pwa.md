# ADR-0006 — PWA from Day One

- **Status:** Accepted
- **Date:** 2026-05-03
- **Deciders:** Owner

## Context

The owner specified a PWA. Trainers often work on the move (training fields, kennels) where connectivity is intermittent — offline-readable views and installability are real value, not vanity features.

## Decision

- Bootstrap with Angular's `ng add @angular/pwa` schematic (service worker + manifest + icons).
- **Manifest:** name, short_name, theme_color, background_color, icon set (192/512 + maskable), `display: standalone`, `start_url: /`.
- **Service Worker** runtime caching configured in `ngsw-config.json`:
  - `freshness` strategy for `/api/v1/**` (network-first with timeout).
  - `performance` strategy for static assets (cache-first).
- **Offline behavior (MVP):** read-only access to dog list, recent notes, today's schedule from cache.
- **Offline mutations (post-MVP):** queue write requests in IndexedDB, replay on reconnect (tracked in `docs/specs/offline-mutations.md` when scheduled).
- **Custom install prompt UI** (not the default browser one) — better conversion and brand consistency.
- **CI budgets:**
  - Lighthouse PWA score ≥ 90 (fail otherwise).
  - Lighthouse Performance ≥ 80 on the dashboard route.
  - axe-core: zero serious/critical violations on Playwright runs.
- **Accessibility target:** WCAG 2.1 AA.

## Consequences

- Frontend-engineer agent's scaffold includes the PWA setup from the first commit.
- `ux-reviewer` agent's `pwa-audit` skill is mandatory before merge.
- Slightly larger initial setup (service worker config, icons) but trivial compared to retrofitting later.

## Alternatives considered

- **SPA without PWA, add later** — every offline-aware feature would need a refactor; rejected.
- **Native mobile app** — out of scope for MVP; PWA covers installability for now.
