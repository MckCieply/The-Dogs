# AUTH-01 — Auth core (Spring Security + JWT + User/Role schema)

## Summary

Foundational backend security layer. Lands the `User`, `Role`, and `user_role` tables, the `UserPrincipal` Spring Security type, JWT issuance + validation plumbing, the default-deny security filter chain, and the project-wide `errors[].code` convention on RFC 7807 responses. Ships **no login endpoint** — only the infrastructure every later auth feature builds on.

Critical blocker for the whole auth pipeline (`AUTH-02` through `AUTH-08`) and for every later RBAC-gated feature (Dogs, Notes, Scheduler).

## Motivation

- Every endpoint in the project will be authenticated by default per [ARCHITECTURE.md §9](../ARCHITECTURE.md). Without the security chain, that default cannot be enforced.
- All subsequent auth features need the `User` table, the principal type, and the JWT signing key already in place. Splitting these into per-feature work would create circular dependencies.
- The `errors[].code` convention is needed by the frontend i18n layer (`I18N-01`) — every error response in the project must carry a stable machine-readable code so the frontend can translate without parsing English `detail` strings. Establishing the convention here means every later endpoint inherits it.

## Scope

### In scope
- Flyway migration creating `app_user`, `role`, `user_role` tables (names below).
- `User`, `Role` JPA entities (Lombok per [ADR-0001](../adr/0001-stack-and-build-tools.md) rules — no `@Data`).
- `UserPrincipal` implementing Spring Security `UserDetails`.
- `JwtService` (sign + verify), `JwtAuthenticationFilter`, `SecurityFilterChain` config with default-deny and explicit `permitAll()` only for `/api/v1/auth/**` and OpenAPI endpoints.
- `BCryptPasswordEncoder` bean (cost 12).
- Project-wide RFC 7807 `@ControllerAdvice` exception handler that always sets `errors[].code` on `400`/`401`/`403`/`404`/`409` responses.
- One protected smoke endpoint `GET /api/v1/me/ping` returning the principal's email + roles (proves the chain works end-to-end).
- Seeded `Role` rows (`ROLE_TRAINER`, `ROLE_ADMIN`) via a separate Flyway migration.
- Testcontainers integration tests: `permitAll` route returns `200`, protected route returns `401` without token / `200` with valid token / `401` with expired token / `401` with bad signature.

### Out of scope
- `/auth/login`, `/auth/refresh`, `/auth/logout`, `/auth/register`, `/auth/forgot-password`, `/auth/reset-password` — each lives in its own spec.
- Rate limiting (handled per endpoint in `AUTH-02`).
- Refresh token table (handled in `AUTH-03`).
- Password reset token table (handled in `AUTH-05`).
- Any frontend code. `AUTH-06` is the first frontend auth spec.
- Multi-tenancy / `trainer_id` scope filters — applied per resource in the resource's own spec.

## Acceptance criteria

- AC-1: `GET /api/v1/me/ping` without `Authorization` header returns `401` with `application/problem+json` body containing `errors[].code = "unauthorized"`.
- AC-2: `GET /api/v1/me/ping` with a valid JWT signed with the configured key returns `200` and the body `{ "email": "...", "roles": ["ROLE_TRAINER"] }`.
- AC-3: `GET /api/v1/me/ping` with an expired JWT returns `401` with `errors[].code = "token_expired"`.
- AC-4: `GET /api/v1/me/ping` with a JWT signed by a different key returns `401` with `errors[].code = "invalid_token"`.
- AC-5: `GET /api/v1/auth/some-public-stub` (a dummy `permitAll` route added just to prove the chain) returns `200` without any token.
- AC-6: A 400 validation error on any protected endpoint returns body shape:
  ```json
  { "type": "...", "title": "...", "status": 400, "detail": "...", "errors": [{ "code": "field_required", "field": "name" }] }
  ```
  with stable `code` values listed in `docs/api/error-codes.md` (created by this feature).
- AC-7: `BCryptPasswordEncoder` bean uses cost ≥ 12 (asserted by a wiring test).
- AC-8: Flyway migration is idempotent — running `mvn flyway:migrate` twice in the integration test is a no-op.
- AC-9: No password, no JWT, and no token claims appear in any log line at any level during the integration test run (asserted by parsing the captured log output).
- AC-10: `mvn verify` exits 0; OpenAPI snapshot (`docs/api/openapi.yaml`) regenerated by springdoc and committed.

## Investigation notes (for the implementer)

- The JWT signing secret comes from env `JWT_SECRET` (HS256) — `application.yml` reads it via `${JWT_SECRET}` with no default in `prod`; `application-test.yml` provides a hardcoded test value. CI sets it via workflow env. **NEVER** commit a secret.
- Access token claims: `sub` (user id, UUID v7 string), `email`, `roles` (array of strings like `ROLE_TRAINER`), `iat`, `exp`. Lifetime: 15 minutes per [ADR-0003](../adr/0003-auth-jwt-rbac.md). Refresh handled in `AUTH-03`.
- Use `spring-boot-starter-oauth2-resource-server` for JWT validation — its `JwtAuthenticationConverter` extracts authorities cleanly. Roles must come from the `roles` claim with the `ROLE_` prefix retained (no `SCOPE_` prefix).
- `@PreAuthorize` on services (not just controllers) per [ARCHITECTURE.md §9](../ARCHITECTURE.md). The smoke endpoint is the first place the pattern is exercised.

## Data model

### `app_user` table

```sql
CREATE TABLE app_user (
    id              UUID PRIMARY KEY,
    email           CITEXT NOT NULL UNIQUE,
    password_hash   TEXT NOT NULL,
    display_name    TEXT NOT NULL,
    enabled         BOOLEAN NOT NULL DEFAULT TRUE,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_app_user_email ON app_user (email);
```

`citext` extension is enabled in the same migration (`CREATE EXTENSION IF NOT EXISTS citext;`).

### `role` table (seeded)

```sql
CREATE TABLE role (
    id   SMALLINT PRIMARY KEY,
    name TEXT NOT NULL UNIQUE
);

INSERT INTO role (id, name) VALUES (1, 'ROLE_TRAINER'), (2, 'ROLE_ADMIN');
```

### `user_role` join table

```sql
CREATE TABLE user_role (
    user_id UUID NOT NULL REFERENCES app_user(id) ON DELETE CASCADE,
    role_id SMALLINT NOT NULL REFERENCES role(id),
    PRIMARY KEY (user_id, role_id)
);
```

### JPA entities (Lombok rules per [ADR-0001](../adr/0001-stack-and-build-tools.md))

```java
@Entity @Table(name = "app_user")
@Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder
@ToString(onlyExplicitlyIncluded = true)
public class User {
    @Id @ToString.Include
    private UUID id;

    @ToString.Include
    @Column(nullable = false, unique = true)
    private String email;

    @Column(name = "password_hash", nullable = false)
    private String passwordHash;

    @Column(name = "display_name", nullable = false)
    private String displayName;

    @Column(nullable = false)
    private boolean enabled;

    @ManyToMany(fetch = FetchType.EAGER)
    @JoinTable(
        name = "user_role",
        joinColumns = @JoinColumn(name = "user_id"),
        inverseJoinColumns = @JoinColumn(name = "role_id"))
    private Set<Role> roles;

    @Column(name = "created_at", nullable = false)
    private OffsetDateTime createdAt;

    @Column(name = "updated_at", nullable = false)
    private OffsetDateTime updatedAt;

    // equals/hashCode by id only (per ADR-0001; UUID v7 assigned in service before persist)
}
```

`Role` is similarly mapped; `EAGER` on roles is acceptable because the per-user role count is bounded (≤ 5 in practice).

## API surface

| Method | Path                       | Auth      | Notes |
| ------ | -------------------------- | --------- | ----- |
| GET    | `/api/v1/me/ping`          | any role  | Returns `{ email, roles }` of the current principal. Smoke endpoint that proves the chain works. |
| GET    | `/api/v1/auth/some-public-stub` | `permitAll` | Returns `{ "status": "ok" }`. Will be removed in `AUTH-02` once `/auth/login` exists — it exists only to assert the filter chain has a working `permitAll` lane. |

Error response shape (RFC 7807 + project-specific `errors[]` extension):

```json
{
  "type": "https://api.thedogs.app/problems/unauthorized",
  "title": "Unauthorized",
  "status": 401,
  "detail": "Authentication is required to access this resource.",
  "errors": [{ "code": "unauthorized" }]
}
```

`docs/api/error-codes.md` is created by this feature and lists every `code` value in use. Each later feature must append to this file (reviewer checks).

Initial codes registered by AUTH-01:
- `unauthorized` — no/missing token.
- `token_expired` — JWT past `exp`.
- `invalid_token` — bad signature, malformed, or unknown issuer.
- `forbidden` — authenticated but lacks the required role.
- `not_found` — resource does not exist or is not visible to caller (no existence leak).
- `field_required`, `field_too_short`, `field_too_long`, `field_invalid_format` — validation primitives.

## UI surface

None. Frontend work starts at `AUTH-06`.

## Security & RBAC

- Filter chain: default-deny. Explicit `permitAll` only for `/api/v1/auth/**`, `/v3/api-docs/**`, `/swagger-ui/**`, `/actuator/health`, `/actuator/info`.
- JWT validation via Spring Security `oauth2-resource-server`. Signing key from `JWT_SECRET` env; no fallback in prod profile.
- `BCryptPasswordEncoder` cost 12.
- `@PreAuthorize` allowed on services (`@EnableMethodSecurity(prePostEnabled = true)`).
- No logging of: `Authorization` header, full token, any token claim, password, password hash. Custom log scrubbing not required at this stage — reviewer asserts by reading the logger calls. Integration test AC-9 catches accidental drift.
- Standard security headers (`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Strict-Transport-Security` in prod profile) configured on the filter chain.
- The smoke endpoint `/me/ping` is gated by `hasAnyRole('TRAINER','ADMIN')` at the **service** layer — confirms the method-level pattern wires correctly with a fresh `User` having `ROLE_TRAINER`.

## Non-functional

- p95 latency for `/me/ping` ≤ 30 ms (local Postgres, single user).
- Testcontainers boots in < 20 s for the integration test suite.
- No external HTTP calls during JWT validation (HS256 is offline; if RS256 lands later, JWKS caching needs a separate decision).

## Open questions

- **HS256 vs RS256.** HS256 with a single shared secret is sufficient for a self-issued, single-tenant backend per [ADR-0003](../adr/0003-auth-jwt-rbac.md). Defaulting to HS256 here; revisit only when we introduce an external IdP.
- **`citext` vs `lower(email)` index.** `citext` keeps the entity field clean but adds an extension. Decision: use `citext` — it is in Postgres core extensions and matches Spring's default `equals` semantics on `String` cleanly.
- **`@CreatedDate`/`@LastModifiedDate` annotations vs DB defaults.** Use DB defaults (`DEFAULT now()`) plus an `@PrePersist`/`@PreUpdate` callback for explicit control. Audit columns elsewhere (`dog.created_at`) will follow the same pattern.
